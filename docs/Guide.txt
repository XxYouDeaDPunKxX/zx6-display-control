Z-X6 DISPLAY CONTROL — 0.1.0-beta.1

Get started
Extract the entire folder, keeping ZX6DisplayControl.Core.dll beside ZX6DisplayControl.exe. Run the EXE.
Requires Windows and .NET Framework 4.7.2 or later. Administrator rights are not required.
Supported device: Z-X6 GPU support bracket with CPU/GPU temperature display.
Connect one Z-X6 holder at a time.
The tested unit reports Turing / UsbMonitor, USB 1A86:5722 / USB35INCHIPSV2.
These USB identifiers are used to find its COM port. Other models and firmware
variants have not been verified, even if they share those identifiers.

Connect AIDA64
In AIDA64 Extreme: Preferences > Hardware Monitoring > External Applications.
Enable shared memory and select the sensors to export. The app only lists exported
sensors. Defaults use TCPU and TGPU1; choose alternatives when necessary.
For Follow usage, export CPU Utilization (SCPUUTI) and GPU Utilization (SGPU1UTI).
Disable AIDA64 LCD > Turing and close the original GPU LCD software: the serial port
can only have one owner. SensorPanel can remain enabled. This app does not change
AIDA64 preferences. Install and configure AIDA64 separately.

Configure each side
Temperature chooses the number shown on that side of the holder. Animation has its
own control sensor; changing it does not change the temperature number.
Pick sensors from the list by name, measurement type, unit and ID. Search is optional.

Modes:
  Loop: Fill, Empty, Bounce or Random. Speed presets: Slow (1 fps), Normal (2 fps),
        Fast (4 fps), Follow usage or Follow temperature.
  Sensor level: map a sensor reading to one of eight bar levels.
  Fixed level: hold a level from 0 (empty) to 7 (full).
Follow usage starts with a 0–100% range. Follow temperature uses the selected display
temperature and a 30–80 °C range. Advanced settings exposes exact ranges, speed,
response time, inversion and level hysteresis. Closing it retains custom settings.
Choosing another unit adapts known ranges (% and °C). For RPM, watts and other units,
review and confirm the range in Advanced settings. No thresholds are inferred for them.
Pause animation holds only that bar; valid temperature numbers continue updating.
The Display tab shows both temperature readouts and animated levels together.
Output sent to display uses the controller’s last completed transmission. Preview · not applied
shows an edited or selected profile that has not been activated yet. This is a
representation of commands: the holder does not report its physical screen state.
Off, disconnected and stopped states clear the preview. Missing draft temperatures
leave the readout blank. Changing modes retains valid ranges, sources and timing.
Choosing an animation preset explicitly replaces its parameters.
The holder displays whole degrees from 0 to 99 °C; fractions are truncated.
Above 99 °C it stays on and shows 99. The app warns with the actual temperature;
sensor-driven animations continue using the original reading.
The app has no controls for brightness, RGB lighting, custom images or firmware updates.

Profiles and saving
Choose a profile under Editing profile on the Display tab. Use profile activates it.
Built-in profiles are permanent: editing one offers Save as new profile, creating a
personal copy with an available name. Save changes updates an existing personal
profile. Revert profile discards profile edits and returns to the saved active profile.
Switching away from modified settings asks Save, Discard or Cancel. No other drafts
are kept or silently saved. A failed save leaves your input available to retry.
During a file operation, editing is temporarily disabled and progress is shown.
Hover over a function or press F1 for contextual help.

Built-in Standard profiles: Classic (steady fill), Activity (speed follows usage),
Thermal (speed follows temperature) and Sensor levels (bar height follows usage).
Built-in Creative profiles: Random, Breathe (slow fill/empty), Counterflow
(CPU fills while GPU empties) and Split tempo (CPU 1 fps, GPU 4 fps).
Profiles lists these separately from My profiles. Select Edit to open one in the
editor, or Duplicate to make a personal copy. New creates a personal profile.
More contains rename, JSON import/export and delete. Built-ins cannot be renamed
or deleted. These collection actions save immediately and preserve unrelated edits.
Export writes the saved version, not an unsaved draft. Import keeps every existing
profile and assigns an available name to the imported copy. Deletion asks for a
confirmation; Cancel is the default. Export first to keep a lasting copy: the
ordinary settings backup rotates again at the next save, including a power toggle.
Older customized built-ins are preserved automatically as personal profiles when
settings load. The original built-ins become available again. The first save after
this migration preserves the old file as settings.before-profile-library-v2.json;
later saves leave that snapshot unchanged.

Daily operation
Settings & About > Close to tray keeps the controller running when the window closes.
This is enabled by default. Minimize to tray is a separate option, initially off.
Double-click the notification-area icon to reopen the window. If Windows hides the
icon, expand the notification-area overflow. Launching the EXE again also opens it.
The tray menu provides window, power, settings and exit actions. Exit stops updates,
requests display off and releases the serial port. Unsaved changes offer Save, Discard
or Cancel. Closing to the tray keeps pending edits in memory until the app exits.
Exit waits for an active file operation and controller cleanup while keeping the
window responsive. If closing takes longer than five seconds, its status remains visible.
If Windows shutdown arrives during a file operation, the app postpones that request
to finish the operation and then closes. Retry Windows shutdown afterwards. Idle
Windows shutdown is allowed; forced termination cannot guarantee unfinished cleanup.
App preferences have independent Save preferences and Revert preferences actions.
They do not apply or discard profile edits. A profile validation error does not
prevent saving preferences.
Start with Windows is opt-in and starts the app in the tray. Settings shows whether
registration points to this copy. If the folder moves, keep Start with Windows
selected and Save preferences to repair the registration.
Appearance offers Light, Dark or System. Theme previews immediately; Save preferences
keeps it and Revert preferences restores the saved theme. Windows high contrast takes precedence. System follows
the Windows app color preference; native file pickers retain Windows styling.
The app scales to the system DPI at startup. It may look blurred when moved to a
monitor using a different scale; per-monitor DPI changes are not supported.

App updates
The app checks GitHub at startup, at most once every 24 hours, including published
beta releases. When a newer app version is available, the window shows a link.
Settings & About > Check for updates checks immediately, even after a failed check.
To turn off automatic checks, clear Check for updates at startup and Save preferences.
This does not disable manual checks or change your profile edits.
Open release opens the new version's GitHub page in your browser. Download the
portable ZIP, Exit the running app, extract the entire new package, then launch
its EXE. Keep the EXE and Core DLL together. Profiles and preferences remain in
your Windows user data folder. If the app folder changes and Start with Windows
is enabled, Save preferences from the new copy to update registration.
No GitHub account is needed. The app does not download or install updates itself.
If GitHub is unavailable, display control keeps running. The check has a 15-second
HTTP timeout; Exit cancels it without waiting. Automatic attempts, including failed
ones, use the separate update-check.json cache and do not rotate profile backups.
Deleting that cache allows a new automatic check at the next startup.

Missing data and recovery
Turning the display off preserves that choice across reconnects and suspend/resume.
Missing temperature data for over five seconds requests display off. Valid data resumes
updates automatically, provided the display is enabled. Losing only an animation sensor
holds that bar while temperature numbers continue updating.
If Windows denies access to AIDA64 shared memory, reopen both apps under the same
Windows account and permission level.
Last reading marks cached values when AIDA64 is unavailable. A stationary reading does
not prove a sensor is stale: AIDA64 supplies no production timestamp in this export.
The AIDA64 and Display status buttons open Connection with current status and
recovery actions. Use Connection > Reconnect to retry immediately. If the port is busy, close its other
owner. If more than one matching holder is detected, disconnect the others.
Updates resume automatically when only one remains. If the controller has stopped,
Reconnect is disabled: Exit and reopen the app to restart it. Diagnostics shows the
detected display.
Diagnostics > Events shows the latest 200 events from the current app session.
Select text and press Ctrl+C to copy it. Last received is the app's receipt time,
not a sensor timestamp. Log-file failures remain visible even if the file cannot
be written. Export diagnostics includes this event history and the available log files.

Local data and removal
Settings & About can open %LOCALAPPDATA%\ZX6DisplayControl. It contains settings.json,
settings.previous.json, update-check.json and up to two 1 MB log files. Invalid settings files are retained
during recovery. Diagnostics exports selected IDs, the active profile, status, counters
and recent events; it does not include AIDA64's INI/license or the entire sensor catalog.
Release checks contact GitHub over HTTPS with the app name and version. GitHub
receives normal connection information, including the IP address. The app does not
upload sensor readings, profiles, diagnostics or logs. Inspect reports before sharing them:
profile names, paths and exception details may contain your Windows user name or
other personal information.
To remove the app: disable Start with Windows, Save preferences, Exit, then remove the extracted
folder. Local settings can be retained for later use.
